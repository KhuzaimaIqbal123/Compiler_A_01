Compiler_A_01 — Lexer Project

C++17 • Regex and No-Regex lexers • Instructions to build & run

Project structure

Compiler_A_01/
├─ include/            # headers: lexer.hpp, lexer_no_regex.hpp, token.hpp
├─ sample/             # sample/program.txt, sample/without_regex.txt
├─ src/                # source files: main.cpp, main2.cpp (or main1.cpp)
├─ .vscode/            # optional tasks/launch
└─ README.html         # ← this file

Requirements

  • g++ (GNU C++) compiler with C++17 support — e.g. via MSYS2 / MinGW-w64.
  • Make sure g++ is on your PATH. Test with: g++ --version
  • Run commands from the project root (the folder that contains src/ and include/).
If you used MSYS2, ensure you installed mingw-w64-x86_64-gcc via pacman and added the relevant \msys64\mingw64\bin to your PATH (user variables are fine).

How to compile & run

1) Regex-based lexer (main.cpp)

Compile from project root:

g++ -std=c++17 src/main.cpp -Iinclude -o lexer_regex

Run (PowerShell):

.\lexer_regex.exe

Or in Command Prompt (cmd.exe):

lexer_regex.exe

2) No-regex lexer (main2.cpp)

g++ -std=c++17 src/main2.cpp -Iinclude -o lexer_no_regex
.\lexer_no_regex.exe

Notes

  • If your compiled executable doesn't find the input, check the path used in main.cpp / main2.cpp. Example constructors in the code use: 
    Lexer lexer1("sample/program.txt");  // recommends this relative path
  • If you see only T_EOF printed, the program did not find or read the input file — ensure the file exists at the expected relative path.
  • PowerShell requires .\ prefix to run a program from the current directory.

Save the token output to a file (optional)

If you prefer the lexer output in a file, redirect stdout:

.\lexer_regex.exe > tokens_regex.txt
.\lexer_no_regex.exe > tokens_noregex.txt

Then open tokens_regex.txt to screenshot or include in your submission.
